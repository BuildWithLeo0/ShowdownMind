# ShowdownMind：Pokémon Showdown LLM Agent 设计方案（人话版）

> 版本：v0.2
> 第一种游戏模式：Gen 9 Random Battle，单打
> 开发环境：Mac，本地 Pokémon Showdown

## 1. 我们到底要做什么

做一个可以自己玩 Pokémon Showdown 的 LLM Agent。

每个回合，它会看到玩家正常能够看到的战局，从合法动作中选择一个，然后根据比赛结果继续调整。

第一版不追求打得很强，先追求三件事：

- 能稳定打完比赛；
- 不会作弊或执行非法动作；
- 每次决定都有完整记录，可以复盘。

这里的“可以复盘”是指我们能看到：

- Agent 当时看到了什么；
- 它有哪些合法选择；
- 如果该版本要求预测，它预测了什么；
- 它最后选了什么；
- 是否调用了备用策略。

LLM 写出的理由只能作为参考，不能当成它内部决策过程的真实解释。

## 2. 第一轮只研究一个问题

第一轮实验只回答：

> 把战局整理成结构化信息，是否比直接给 LLM 战斗日志更好？

比较对象：

```text
版本 A：简化的原始战斗日志 + 合法动作
版本 B：结构化战局 + 相同的合法动作
```

两个版本使用相同模型、相同对手、相同模型参数和相同比赛数量。

第一轮不同时加入伤害计算、隐藏信息推测、Planner 或搜索，否则即使胜率提高，也无法知道是哪项能力产生了作用。

## 3. 第一版每回合怎么工作

```text
Showdown 给出当前战局
        ↓
Python 只提取玩家可见信息
        ↓
Python 生成所有合法动作
        ↓
LLM 调用一次，选择一个动作
        ↓
Python 检查输出格式和动作是否合法
        ↓
合法：提交给 Showdown
失败：使用有记录的备用动作
        ↓
保存本回合记录，等待下一回合
```

LLM 不直接输入 Showdown 命令，只能选择程序提供的动作 ID，例如：

```text
A. 使用 Earthquake
B. 使用 Protect
C. 换上 Rotom-Wash
D. 使用 Earthquake 并太晶化
```

这样可以避免模型拼错名字、使用不存在的招式或忘记强制换人。

## 4. 第一版包含什么

第一版只包含：

- 在 Mac 上运行本地 Pokémon Showdown；
- 用 Python 和 `poke-env` 连接游戏；
- 让内置的简单 Bot 自动对战；
- 读取玩家可见的战局；
- 生成合法动作列表；
- 正常情况下只调用一次 LLM 选择动作；
- 检查动作并在失败时兜底；
- 保存每场比赛和每回合记录；
- 自动统计稳定性、胜率、耗时和费用。

第一版明确不包含：

- 猜测对手的隐藏招式和道具；
- 精确伤害计算；
- 长期战略 Planner；
- ReAct 式反复思考和调用工具；
- 搜索未来回合；
- 多个 LLM 互相讨论；
- Agent 框架；
- 强化学习；
- 自动组队；
- 跨比赛长期记忆；
- 在线挑战真人。

## 5. 绝对不能偷看对手信息

本地 Showdown 服务器知道双方完整队伍，但 Agent 不能看到对手尚未公开的信息。

程序必须维护两份数据：

```text
玩家视角
用于实时决策
只包含比赛中正常公开的信息

赛后答案
只用于比赛结束后的评测
可以包含对手真实队伍、招式、道具和特性
```

两份数据不能使用同一个输入对象传递给 Agent。

需要自动检查：

- 未公开招式不能出现在 LLM 输入中；
- 未公开道具和特性不能出现在 LLM 输入中；
- 对手完整队伍只能在比赛结束后用于评分；
- 以后做搜索时，只能使用“猜测的对手配置”，不能使用真实答案。

如果这里做错，胜率再高也没有研究价值。

## 6. 第一版不是五个复杂模块

完整 Agent 以后可以逐渐拥有“眼睛、笔记本、计算器、计划和大脑”，但不能一开始全部实现。

### 第一版：眼睛 + 大脑

```text
眼睛：整理当前公开战局
大脑：LLM 从合法动作中选择
```

这里所谓的“记住已公开信息”，由 `poke-env` 的当前 Battle 状态和我们保存的公开事件负责，不是让 LLM 自己维护聊天记忆。

### 第二阶段：增加信念

将“事实”和“猜测”分开：

```text
事实：对手已经使用 Shadow Ball
猜测：对手有 40% 概率携带 Choice Scarf
```

每个猜测必须带概率和依据，不能把猜测写成事实。

### 第三阶段：增加计算器

程序计算：

- 属性克制；
- 可能的速度关系；
- 伤害范围；
- 击杀概率；
- 换人后的场地伤害。

因为对手参数可能未知，计算结果应当是范围或多种情况，不能假装成一个精确答案。

### 第四阶段：增加轻量 Planner

Planner 只维护本局的大方向，例如：

```text
保留 Dragapult 用于后期收割
优先解决 Kingambit
暂时保留太晶
```

Planner 不需要每回合调用。只在以下情况更新：

- 比赛开始；
- 有宝可梦倒下；
- 关键道具、招式或速度关系公开；
- 任意一方使用太晶；
- 原计划明显失效。

每回合真正选择动作的仍然是 Policy。

### 第五阶段：可选搜索

程序可以猜测几种可能的对手配置，再调用 Showdown 模拟器比较不同动作的结果。

这叫“使用外部模拟器进行搜索”，不代表 LLM 自己已经拥有世界模型。

由于隐藏状态采样和战局复制比较复杂，搜索属于可选研究方向，不是项目必须完成的功能。

## 7. 不使用 ReAct，也不使用 Agent 框架

第一版采用一次调用：

```text
当前状态 + 合法动作 → Policy → 一个动作
```

不采用 ReAct：

```text
思考 → 调工具 → 再思考 → 再调工具
```

原因是 ReAct 会让每回合产生多次模型调用，增加成本、延迟和不可控行为，也会让实验很难判断提升来自哪里。

以后加入伤害工具时，程序先计算，再把结果一次性交给 Policy。LLM 不自行决定要不要反复调用工具。

也不需要 LangGraph、AutoGen 等通用 Agent 框架。Showdown 已经提供清楚的回合循环，直接用 Python 实现更容易控制和测试。

最终建议：

```text
第一版：Policy
以后：事件触发的 Planner + 每回合 Policy
暂不采用：ReAct 循环
```

Planner 和 Policy 只是两个普通 Python 类，不需要额外框架。

## 8. LLM 出错怎么办

可能出现：

- 请求超时；
- 返回的不是正确 JSON；
- 选择了不存在的动作；
- 模型服务暂时不可用。

处理方式：

```text
第一次输出错误
→ 告诉模型哪里不符合格式，允许修复一次

仍然失败或超时
→ 从合法动作中使用固定种子的随机备用动作
```

备用动作的目的只是让比赛继续，不负责替 LLM 打得更好。

这里的“修复一次”只用于纠正 JSON 或非法动作，不允许模型进入反复思考—调用工具的循环。

实验必须记录：

- 哪些回合使用了备用动作；
- 每局触发了多少次；
- 完全不调用 LLM、只使用同一备用策略的基线表现。

否则完整 Agent 的胜率可能其实来自备用策略。

## 9. 怎么公平地比较

最低对照组：

- 随机合法动作 Bot；
- 最高基础威力 Bot；
- `poke-env` 简单规则 Bot；
- 只使用备用策略的 Bot；
- 原始日志 LLM；
- 结构化战局 LLM。

公平规则：

- 对战双方轮换 p1 和 p2；
- 各版本使用同一个对手池；
- 固定 Showdown、`poke-env`、模型和提示词版本；
- 模型参数保持一致；
- 中止、超时和断线必须单独报告，不能直接删除；
- 每次实验只改变一个主要变量。

比赛数量分成两种：

```text
稳定性测试：连续完成 100 场
版本强弱比较：每组至少 200 场，并报告置信区间
```

如果以后要发布可靠结论，再将关键对局提高到约 1,000 场。

主要指标：

- 胜率和置信区间；
- 模型输出失败率；
- 备用动作触发率；
- 每回合耗时；
- 每场 Token 和费用；
- 以后加入预测后，再统计预测准确度和概率校准。

100 场只能说明程序是否稳定，不能单独证明某个版本更强。

## 10. 开发顺序

### 第 0 步：跑通 Showdown

让两个内置 Bot 在本地连续完成 20 场比赛。

### 第 1 步：完成基础 Policy

让 LLM 从合法动作中选择，正确处理超时、格式错误、强制换人和太晶动作。

连续完成 100 场比赛。

### 第 2 步：完成第一轮研究

比较“原始日志 LLM”和“结构化战局 LLM”。

每个主要对局至少运行 200 场，并生成报告。

### 第 3 步：增加对手信念

研究对手招式、道具和速度猜测是否提升表现。

### 第 4 步：增加计算工具

研究伤害、速度和换人风险计算是否提升表现。

### 第 5 步：增加轻量 Planner

研究显式保存本局战略是否比每回合重新判断更好。

### 第 6 步：决定是否做搜索

只有前面部分已经稳定，并且搜索对应明确研究问题时才实现。

## 11. 第一版怎样才算完成

同时满足：

- 本地 Showdown 可以一条命令启动；
- 内置 Bot 可以自动对战；
- LLM 只能从合法动作中选择；
- Agent 只能看到玩家正常可见的信息；
- 连续完成 100 场，无死锁和人工干预；
- 模型失败时比赛仍能继续；
- 每个回合都能复盘输入、输出和最终动作；
- 可以统计胜率、置信区间、耗时、费用和备用动作触发率；
- 可以比较原始日志与结构化战局两个版本。

第一版的目标不是打败高手，而是建立一个不会作弊、运行稳定、实验公平的平台。

## 12. 最终形态

```text
                    Pokémon Showdown
                            ↓
                  只读取玩家可见战局
                            ↓
              ┌─────────────────────────┐
              │ 事实 │ 概率信念 │ 计算结果 │
              └─────────────────────────┘
                            ↓
                  可选的轻量 Planner
                            ↓
                    每回合 Policy
                            ↓
                  合法性检查和备用动作
                            ↓
                         执行动作
```

最重要的原则：

> 先让它诚实、稳定地玩，再让它聪明地玩；每次只增加一种能力，并通过公平实验验证是否真的有效。
